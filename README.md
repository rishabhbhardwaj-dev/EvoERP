# EvoERP Documentation Starter Pack

This folder contains the working documentation set for the 8-week EvoERP delivery.

## Current status

These are **working engineering documents**, not a final replacement for the mentor's 233-page blueprint.

The plan is to:
1. Freeze the 8-week scope.
2. Confirm the stack and architecture with the mentor.
3. Evaluate open-source projects and licensing.
4. Finalize database and API contracts.
5. Design the UI/UX and module workflows.
6. Implement, test, deploy, and continuously update these documents.

## Document map

- `requirements.md` — product scope and functional requirements
- `oss-evaluation.md` — open-source project evaluation and reuse decisions
- `architecture.md` — system architecture and major technical decisions
- `design.md` — UI/UX, module workflows, navigation, and design system
- `database.md` — database entities, relationships, tenancy, and indexing
- `api.md` — REST API conventions and endpoint contracts
- `module-specifications.md` — per-module specification template and module register
- `security.md` — authentication, RBAC, tenant isolation, audit and security controls
- `testing.md` — test strategy and acceptance testing
- `deployment.md` — environments, deployment, backups and operations
- `development-workflow.md` — Git, branching, PRs, coding standards and delivery flow
- `roadmap.md` — 8-week execution plan and milestones
- `decisions.md` — Architecture/technology decision log

## Rule

When a requirement or architectural decision changes, update the relevant document instead of relying only on chat messages.
